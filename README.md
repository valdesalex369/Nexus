# NEXUS

An intelligence operating system: bounded, auditable infrastructure that turns model
output into **verified execution**.

Not a chatbot. Intelligence and execution are different things; the gap between them
is evidence — action, verification, persistence, and measurable outcome.

## What works today

| Capability | Verified behavior |
|---|---|
| **Opportunity Radar v0** | One public Federal Register event becomes a provenance-bound claim, visible uncertainty, explainable Wayfinder score, Argus/Nova deliberation, Nexus policy ruling, VERIFIED/HUMAN_GATE result, hash-chained ledger evidence, and four-panel dashboard state. |
| **Event Ledger** | Append-only and hash-chained. `verifyChain()` names the first altered record; database triggers reject `UPDATE` and `DELETE`. |
| **Policy Engine** | Rules every action `allow`, `require_approval`, or `deny` across capital levels and blast-radius tiers. |
| **Task Router** | Routes by capability, not provider. |
| **Gauntlet** | `build → critique → verify → score → revise`, bounded on independent axes. |
| **Evaluation** | Verifiers produce command/output evidence rather than model opinions. |
| **Agent Contracts** | Grants make recursion safe because authority only narrows. |
| **Wayfinder** | Scores transparent components and vetoes irreversible catastrophe. Novelty scores zero. |
| **Intake** | Treats ingestion as untrusted and quarantines injection- or credential-shaped content. |

The core system runs with zero API keys. Opportunity Radar uses a free public
government endpoint.

## Hackathon demo

```bash
npm install
npm test
npm run typecheck
npm run radar               # live run, then dashboard on http://127.0.0.1:8787
npm run radar -- --once     # live run, verify, write state, and exit
```

The dashboard reads only `data/runs/latest.json`, generated by the pipeline. It
labels live versus fixture state, preserves uncertainty, and marks initial
Wayfinder commercial inputs as experiment priors rather than forecasts.

Deterministic offline replay:

```bash
npm run radar -- --fixture test/fixtures/federal-register.json
```

See [`docs/OPPORTUNITY_RADAR_V0.md`](docs/OPPORTUNITY_RADAR_V0.md) for the branch
audit, acceptance tests, evidence contract, live path, and limitations.

## Other commands

```bash
npm run doctor
npm run gauntlet -- "make the suite pass" --verify-cmd "npm test"
npm run nexus -- ledger
npm run nexus -- verify
```

Copy `.env.example` to `.env` to enable model-provider adapters. No provider key is
required for Opportunity Radar v0.

## Design decisions

- **Unknown cost stays unknown.** Only verified pricing enters the table.
- **A model may not grade its own work.** Critique excludes the builder provider.
- **Termination is measurable.** Iterations, budget, timeout, threshold, and stall.
- **No build step.** Node 22.18+ runs TypeScript natively; SQLite and tests are built in.
- **A score is not a forecast.** Radar exposes every component and marks provisional
  inputs `EXPERIMENT_PRIOR_NOT_FORECAST`.

## Status

The first public-source adapter has completed a real Federal Register run without an
API key. Model-provider adapters remain unproven against live APIs. Radar v0 proves
one bounded loop; it does not prove buyer demand, revenue, precision@5, or independent
multi-source corroboration.
